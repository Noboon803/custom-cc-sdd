# kiro-verify-completion

## 概要

このスキルは、誤った完了の主張を防ぐ。タスク、修正、または機能は、主張のスコープに見合った、新しく取得した証拠によって裏付けられている場合にのみ完了である。

## 使用するタイミング

- タスクが完了したと言う前
- バグが修正されたと言う前
- テストが合格したと言う前
- 自律実行で次のタスクに進む前
- 機能レベルの検証から `GO` を報告する前
- 他のサブエージェントの成功レポートを信用する前

初期の計画段階や、推測に基づくステータス更新には、このスキルを使ってはならない。

## 入力

以下を提供する：
- 確認対象の正確な主張
- 主張の種類：
  - `TASK`
  - `FIX`
  - `TEST_OR_BUILD`
  - `FEATURE_GO`
- コントローラーが特定した検証コマンド
- 新しく取得したコマンド出力と終了コード
- 該当する場合は、関連するタスク ID、要件 ID、設計の参照
- 機能レベルの主張の場合：
  - 要件の網羅状況
  - 設計との整合状況
  - 統合の状況
  - ブロックされたタスクの状況

## 出力

次のいずれかを返す：
- `VERIFIED`
- `NOT_VERIFIED`
- `MANUAL_VERIFY_REQUIRED`

あわせて以下も返す：
- 確認対象とした主張
- 使用した証拠
- スコープと証拠の不一致（あれば）

`spec.json` で指定された言語を使う。

## ゲート関数

1. 正確な主張を特定する。
2. その主張を証明する、正確なコマンドまたはチェックリストを特定する。
3. 現在のコード状態から新しく取得した証拠を必須とする。
4. 終了コード、失敗件数、スキップされたスコープ、および欠けているカバレッジを確認する。
5. 証拠よりも広い主張は却下する。
6. 必須の検証を完了できない場合は、`MANUAL_VERIFY_REQUIRED` を返す。
7. そこまで済んで初めて、主張を認める。

## 主張の種類ごとのルール

### TASK
以下を必須とする：
- タスクローカルな確認の証拠
- レビューで未解決のブロッキングな指摘事項がないこと
- タスクの境界と整合した証拠

### FIX
以下を必須とする：
- 元の症状が解消されたことを示す証拠
- 関連する確認のスコープにおいて、より広範なリグレッションがないこと

### TEST_OR_BUILD
以下を必須とする：
- 実際のコマンド出力
- 終了コード
- 無関係なチェックからの推論ではないこと

### FEATURE_GO
以下を必須とする：
- テストスイート全体の結果
- ビルドされた成果物が、最初の使用可能な状態に到達することを示す、ランタイムのスモーク起動の結果
- 要件の網羅に関する評価
- タスク横断の統合に関する評価
- 設計とのエンドツーエンドの整合に関する評価
- ブロックされたタスクに関する評価

テストスイートの合格だけでは、`FEATURE_GO` には不十分である。

## 停止／エスカレーション

以下の場合は `MANUAL_VERIFY_REQUIRED` を返す：
- 正規の検証コマンドが分かっていない
- 必要な環境が利用できない
- 必須の手動確認の手順を実行できない

以下の場合は `NOT_VERIFIED` を返す：
- コマンドが失敗した
- 証拠が古い
- 証拠が部分的である
- 主張が証拠を超えている
- 機能に、未解決のブロックされたタスクや、網羅されていない要件がまだある

## よくある自己正当化

| 自己正当化 | 実際 |
|---|---|
| 「サブエージェントが成功したと言っていた」 | 報告された成功は、確認の証拠ではない。 |
| 「テストは以前に合格していた」 | 新しく取得した証拠のみが有効である。 |
| 「lint が通ったので、ビルドも問題ないはずだ」 | lint はビルドの成功を証明しない。 |
| 「テストが通り、ビルドも成功したので、動くはずだ」 | 型消去、モジュールの読み込み、ネイティブ ABI、起動時の設定の問題によって、実行時に失敗することはなおありうる。 |
| 「すべてのタスクにチェックが付いたので、機能は完成だ」 | `FEATURE_GO` には、網羅、統合、設計との整合も必要である。 |

## 出力形式

```md
## Verification Result
- STATUS: VERIFIED | NOT_VERIFIED | MANUAL_VERIFY_REQUIRED
- CLAIM_TYPE: TASK | FIX | TEST_OR_BUILD | FEATURE_GO
- CLAIM: <正確な主張>
- EVIDENCE: <コマンド／チェックリストとその結果>
- GAPS: <スコープと証拠の不一致、または欠けている検証>
- NOTES: <確認されなかった場合の次のアクション>
```
